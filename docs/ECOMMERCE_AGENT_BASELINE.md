日期：2026-10-21（Asia/Shanghai）。Loop 00 实施记录。

## 当前执行顺序

三岗业务优先，暂停统一任务/队列扩展，账号角色和权限配置后置；现有业务权限继续校验。复用已有业务入口和 Skill，不以统一任务中心作为业务实施前置。本轮从财务数据质量开始，再处理运营 Listing 的资料与草稿校验、客服正文与交接。

仓库中找到岗位 Skill、项目规范、事件接入文档及 `docs/refund.md`，未定位到独立的电商运营业务附件。现有规则作为实现依据；缺失的实际样本、站点要求、渠道能力和财务口径保留为待联调资料，不补造。

### 2026-10-21：05.1 接口复测与 06.1 客服正文隔离

实际改动与验证：

- 财务隔离 API 脚本修正 `automation_runs.output_text` 为真实字段 `output_preview`，复测通过。真实 XLSX、FastAPI 路由、随机账号登录、岗位权限、文件归属/下载、同步结果、真实 Celery handler 与产物恢复共 11 类检查；不包括 RabbitMQ 投递。一次性容器、文件均清理。
- 新增 `app/services/customer_reply_contract.py`：严格解析客户正文、内部建议、人工复核布尔值；字段缺失、重复、类型错误、混合段落均进入人工复核。解析失败正文为空，原始输出和说明仅内部保存，运行/生成步骤标记受阻。
- 客服服务在原 `reply_draft` 保存纯正文，在 metadata 分字段完整保存内部建议/原始失败输出，并由 API 明确返回复核与校验状态。复用现有数据库，不增加迁移。草稿 ID 与写回信息保存回消息，刷新后可读取。
- 自动写回需同时满足低风险、决策为待自动回复、结构有效及无人工复核标记。ERP 查询失败/没有订单记录时不自动写回；尺码/优惠政策缺引用时保留草稿。这里只修既有资料检查，客户与订单的强关联核验仍待补齐。
- 外部请求只传经过验证的客户正文和必要路由字段；内部建议、转人工原因、原始输出和草稿内部 metadata 不进入执行请求。重试再校验持久请求，旧版混合草稿禁止执行/发送；重试用的业务正文不再按日志的 500 字符限制截断。最终发送仍需审核且以真实渠道回执为准。
- 对话 Skill 和收件箱分别展示客户正文、客服内部建议、人工复核标记；不把本地保存草稿描述为已完成外部写回/发送。
