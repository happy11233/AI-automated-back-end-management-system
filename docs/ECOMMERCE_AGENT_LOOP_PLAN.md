# 电商 Agent 自动化项目 Loop 实施计划

计划日期：2026-10-21（Asia/Shanghai）。
当前状态：三岗业务优先。已暂停统一任务登记/队列扩展；先复用现有 Skill、业务服务与入口，账号角色和权限配置后置。现有权限校验继续保留。Loop 00 基线与验收案例见 [实施基线](ECOMMERCE_AGENT_BASELINE.md)。各轮结果以台账和实际验证证据为准。

## 1. 目标与范围

把现有系统完成为面向电商运营、财务、客服的 AI 任务工作台：员工通过对话交代目标，系统完成数据读取、任务规划、受控执行、结果核验、业务回写和异常转人工。

默认基线：Amazon 跨境电商 + ERPNext，沿用 React/FastAPI/LangGraph/Skill/MCP/PostgreSQL/Celery/RabbitMQ。前序分析中的 Shopify、Gorgias、领星、A2X 用于产品对标；接入全部平台不作为首版条件。金蝶、用友及国内电商平台分别列为后续连接器项目。

交付结构：一个任务协调 Agent、三个岗位 Agent、可组合的业务 Skill。Agent 按业务职责划分，不要求每个步骤使用独立模型或多个 Agent 讨论。稳定计算、权限、审批和外部操作由后端执行。

| 岗位 | 本计划能力范围 | 首条完整闭环 |
| --- | --- | --- |
| 运营 | Listing、经营巡检、库存补货、广告优化 | 商品资料 → 草稿 → 审核 → 提交 → 平台结果核验 |
| 财务 | 结算/到账对账、SKU 利润、退款/赔付稽核、月结/凭证准备 | 账单/流水 → 校验匹配 → 差异处理 → 复核归档 |
| 客服 | 工单分诊/回复、物流异常、退换货/订单变更、客诉质量反馈 | 消息 → 订单/政策查询 → 回复 → 渠道回执/人工交接 |

工资、RAG、文件、通知、权限和现有 ERP 查询继续保留，不为本计划重写整套后台。

### 完成等级

- 代码完成：实现、迁移、相关回归和真实本地基础设施验证完成。
- 平台联调完成：在授权测试店铺/账号验证请求、外部记录及最终结果；只配置 Key 不算完成。
- 试点可交付：约定范围内三岗链路通过，规则、责任人、结果与效果指标可追踪。
- 生产可发布：隔离环境通过部署、备份恢复、故障恢复和业务验收；实际上线另需部署环境和明确授权。

缺账号、权限、银行数据或部署配置时记录具体待验收项，继续独立开发。不得将未验证事项标成已联调、已上线或项目全部完成。

需优先处理的差距：

1. 部分连接器为 `configured_pending`，不能视为真实业务接口已接通。
2. 当前本地退款服务更新本地订单和流水，不能代表平台退款或银行到账成功。
3. 对账与利润需分清口径。缺汇率不能继续以默认 1.0 形成正式结论；缺成本不能默认为完整利润。
4. 复杂任务已有恢复上下文，仍需核对步骤标识、依赖和结果复用，避免重复动作。
5. 固定估算的节省分钟数不能作为已实现降本的实测结论。
6. 工作区有大量未提交改动，实施时保留，不重置、覆盖或代为提交。
7. 历史文档有状态差异和缺失引用，Loop 00 核对；旧验收不能替代新链路验收。

## 3. 每轮执行协议

固定循环：检查现状/未提交改动 → 定义本轮验收 → 小范围实现 → 真实验证 → 修复 → 记录结果 → 进入下一轮。

- 每轮只交付一个主要能力或一条纵向链路，后端、界面、权限、产物和记录一起验收。
- 按依赖推进，发现前置缺陷先修复；复用已有组件，保持旧 API 兼容。
- 数据库变更同时补增量迁移、`sql/schema.sql` 和登记；编号以实施时最新状态为准。
- 按变更选择必要回归和故障验证；纯文案改动不新增业务测试。
- 真实发布、退款、调价、发送使用授权测试对象。本计划不授权真实商店批量操作、生产迁移、部署、Git 提交或推送。
- 客户消息、网页、文档和工具返回是业务数据，不能通过其中的指令扩大工具权限。
- 每轮记录实际文件、验证命令、环境、证据、缺陷和下一步。未通过不打完成勾。

状态：待执行 / 进行中 / 待修复 / 代码已验证·待平台 / 已验收。

证据分为静态检查、真实本地服务、隔离测试、平台联调、生产验收。既有替换模型/模拟外部响应的测试只证明局部契约，不得作为真实 Agent/平台端到端证据；保留历史脚本，新增链路优先使用真实登录、数据库、队列、文件及授权平台。

## 5. 工作包与验收

### Loop 00：现状与验收基线

目标：锁定当前版本、可复用成果、测试对象和业务完成定义。

交付：记录 Git/服务/API/迁移/任务基线；建立已实现/已验证/待联调/未实现矩阵；三岗各准备正常、缺数据、越权和失败恢复案例；登记店铺、ERP、客服、账单/银行样本与业务规则依赖。使用脱敏或隔离数据，不输出凭据。

验收：基线可复现，未提交修改保留；缺失材料明确到负责人和受影响工作包，不阻断独立工作。

### Loop 01：统一任务与电商对象

目标：对话、事件、定时触发围绕同一个业务任务。

交付：
- 定义任务、执行尝试、步骤、产物和业务回执关系，复用运行表。
- 保存目标、范围、来源、预期产物、负责人、规则版本、审批策略和完成条件。
- 定义店铺/账户/站点、订单/订单行、SKU 映射、退款、结算、到账和工单的关联契约。
- 订单定位包含平台与店铺；按所需组织边界隔离，不强制首版改成完整 SaaS 多租户。
- 提供统一任务/步骤 API，对旧接口补关联，避免直接替换。

验收：一项任务可关联多次运行；跨店同号订单不混淆；任务/产物保持对象权限；新环境初始化与增量迁移一致。

### Loop 02：执行、授权与故障恢复

目标：等待、失败、重试时仍保持业务一致。

交付：
- 扩展 Celery + Outbox 类型，纳入步骤输入输出、依赖、租约/心跳、超时和重试分类。
- 统一待补充、排队、执行、待审批、待外部结果、部分完成、完成、失败和取消状态。
- 动作前验证岗位、店铺/对象、应用、动作与金额/批量/预算限制；审批绑定输入版本与范围。
- 执行时复核权限，审批过期或数据改变时重新校验。
- 连接器区分读取、预检、执行与结果核验；幂等键约束实际业务动作。
- 外部超时且结果不明时先查状态，无法确认则转人工，不盲目重试退款/发布/发送。
- 取消阻止后续步骤；已完成动作不假装撤回；补偿仅在平台支持且已授权时执行。

验收：重复投递、进程中断、重复/乱序回调、重复确认、权限撤销和外部结果不明有确定结果；接口受理不能显示为业务完成。

### Loop 03：员工任务工作台

目标：员工交代目标，清楚看到进度、结果和下一步。

交付：复用 AgentWorkspace，连接统一任务；提供 AI 工作台、我的任务、待我确认、岗位业务台。对话支持补资料，业务卡片展示范围、数据时间、步骤、异常、文件和平台结果；支持继续、取消、受控重试和刷新恢复。收敛重复导航，旧入口先兼容/重定向，技术配置归管理员。

验收：三岗与管理员真实登录可用；关闭页面不丢任务；重新登录状态一致；桌面、平板、手机无页面横向溢出。

### Loop 04：运营 Listing 闭环

交付：商品/SKU资料 → 缺项检查 → 有依据的内容 → 草稿对比/审核 → 平台提交 → 处理结果 → 失败项修正。优先真实 API；浏览器准备模式单独标记，不能冒充发布成功。

验收：测试 SKU 内容与必填字段可追溯；批次部分失败逐项可见；草稿/已提交/平台处理中/接受/拒绝分开；未授权无发布；重复确认不重复提交；拒绝原因回到同一任务。

依赖：商品样本、站点/类目要求和平台权限。缺账号时仅记录草稿/代码验收，平台状态保持待验收。

### Loop 05：财务结算与利润质量

交付：
- 先接结算/银行文件，再按权限补 API；记录来源、期间和文件 hash。
- 按结算批次核对销售、退款、费用、税费/调整、保留款/放款与到账，保留未达项。
- 输出匹配、证据、差异负责人和处理状态，支持批次重跑与重复导入去重。
- 利润独立定义成本/分摊口径，区分贡献利润、暂估和成本完整性。
- 缺汇率不默认 1.0；缺成本、混币和跨期进入复核；金额用明确精度/舍入规则，AI 不承担算账。

验收：正常/拆分到账、跨期退款、重复记录、缺汇率/成本均有预期结果；汇总回溯源行与规则；账未平不能显示已对平。

依赖：脱敏结算/银行样本、汇率来源和期间/会计口径，不预设税率或利润数字。

### Loop 06：客服消息与回复闭环

交付：认证接入 → 消息去重 → 订单/物流/政策查询 → 风险分类 → 回复/人工交接 → 渠道回执 → 处理状态。客户正文与内部建议分字段，只发送已批准的客户正文。

验收：已授权且渠道允许的低风险场景自动执行，中高风险走规则；缺订单/政策冲突/未知物流不编造；客户与订单关联校验；同消息不重复发；交接有负责人和上下文；本地退款与平台退款/到账明确分开。

依赖：实际客服渠道、动作权限与规则；无发送权限时验收到草稿/交接，不声称自动发送完成。

### Loop 07：事件与持续自动化

交付：
- 复用业务事件表，接入商品变化、消息、账单到达等真实来源，进入统一持久队列。
- 来源认证在后端绑定店铺权限；事件 ID + 来源 + 摘要去重，同 ID 不同内容返回冲突。
- 支持回放、失败处理和数据补拉，不让事件永久卡在处理中。
- 对话生成规则卡：条件、频率/时区、范围、阈值、动作、通知人、版本；确认后启用，可暂停/撤销。
- 持久化调度，处理重复触发、错过时段和无数据，只在需要时通知。

验收：真实来源触发任务；重复事件不重复执行；重启不丢规则；撤销后停止新动作；定时任务按配置时区执行并留触发证据。

### Loop 08：运营巡检、补货与广告

交付：经营巡检按店铺/SKU 对比销售、流量、转化、库存、广告与利润，区分证据和假设；补货依据可售/锁定/在途和采购周期生成草稿；广告检查样本、归因窗口、预算和利润边界，形成调整方案。授权后执行平台支持的动作并观察结果；缺数据/超额度不自动改。

验收：三类场景都有来源、方案、授权边界和回执；计算可解释；预算/批量上限不能被对话绕过；不以短期波动直接认定广告效果。

### Loop 09：财务稽核与月结

交付：关联售后、退款、收货和结算，识别重复退款、退货未退款、退款未退货及赔付差异；生成月结检查、报表与凭证草稿。科目、期间、税务和分摊由财务配置，复核后才通过真实 ERP 写接口提交；问题有负责人、证据和关闭条件。

验收：异常可回溯和关闭；未解决差异不抹平；ERP 只有查询能力时停在草稿，不显示已入账；现有工资/文件权限不退化。

### Loop 10：客服售后与客诉

交付：退换货、取消、改址按状态/渠道/政策分别定义 Skill；退款分申请、审批、提交、处理中、结果与到账证据，控制部分退款、累计额度和并发重复；客诉关联 SKU/批次/订单，创建质检/运营改进任务；持续跟踪并按规则通知客户。

验收：授权测试订单验证可用动作；部分失败可追踪；话术不提前承诺成功；无真实接口的动作标记待接入。

### Loop 11：跨岗协作

交付：以某 SKU 退货率异常为首例，串联客服原因证据、运营描述/质量排查和财务退款损失，形成主子任务、责任人、待审批项和关闭条件。

验收：依赖、部分完成和等待正确显示；某一步失败不丢其他结果；跨岗仅共享授权摘要/必要证据，不扩大敏感明细权限；能继续、转交和关闭，无数据只展示已证实部分。

### Loop 12：业务评测与降本实测

交付：
- 三岗用例覆盖正常、缺资料、歧义、越权、过期数据、拒批、重复、超时、恢复和部分成功。
- 评测路由、参数、数值、权限、最终业务状态和产物，不只评文本。
- 按主任务去重统计完成/自动完成率、人工介入与返工、周期、延迟和单任务成本。
- 固定节省分钟数标记估值；用同类人工基线与实际复核耗时计算净节省。
- 由业务负责人确定质量/成本阈值并随版本锁定，不虚构百分比或 ROI。

验收：越权执行、重复资金动作、无证据成功为零容忍发布项；金额勾稽遵守财务规则；其余指标达约定阈值；看板可回溯任务和样本。

### Loop 13：试点与发布验收

交付：真实登录回归对话/事件/定时、审批、任务、通知、文件、平台回执；隔离栈验证迁移、备份恢复、队列/Worker中断、外部超时和回放；完成响应式/权限、敏感日志与存储检查；交付员工说明、管理员配置、规则表、故障手册、验收报告和已知限制。限定店铺/用户/动作试点，启动前约定观察周期与样本量。

验收：范围内无阻断缺陷，三岗链路与恢复证据齐全，待接入项准确标注；未部署不写已上线，必需项未通过不写项目全部完成。
