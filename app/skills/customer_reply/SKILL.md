# 客服回复草稿 Skill

## 适用场景

客服需要根据客户消息、订单号、物流单号、售后诉求或退款退货问题生成回复草稿。

典型触发：

- 客户询问物流、退货、换货、尺码、优惠码、发货时效。
- 客户提出退款、投诉、差评、拒付等高风险售后诉求。
- 聊天或客服收件箱要求自动生成客服回复并保存草稿。

## 不适用场景

- 用户只是查询客服规则，应优先走 RAG。
- 用户要求直接退款、赔付或删除评价，必须转人工或审批。
- 运营或财务岗位请求客服私有消息处理，应由权限闸门拒绝。

## 权限规则

- 仅客服岗位或管理员可执行。
- 非管理员必须启用 `customer-service-message-loop`。
- ERP 查询只能访问客服岗位资源：Customer、Sales Order、Delivery Note、Issue、Return request。
- RAG 查询必须继续带当前用户 ID、岗位、站点、店铺、字段、敏感级别、owner/team/grant scope。

## 执行步骤

1. 校验岗位和 AI 应用启用状态。
2. 创建 `customer_service_messages` 记录。
3. 自动识别意图和风险等级。
4. 按客服岗位权限查询 ERP 和 RAG。
5. 生成结构化回复，客户正文与客服内部建议分字段保存；结构解析失败时正文留空，原始输出仅供内部复核。
6. 仅低风险、资料充分、决策允许且无人工复核标记时自动写回外部草稿；其余保留本地草稿。最终发送继续要求审核与渠道回执。
7. 高风险创建审批或转人工记录。
8. 写入事件时间线、运行记录、平台草稿和审计。

## 输出格式

- 客户消息 ID。
- 意图和风险等级。
- 客户回复正文、内部建议、人工复核与结构校验状态。
- ERP/RAG 引用摘要。
- 平台草稿 ID 和写回状态。
- 审批 ID 或人工介入信息。

## 安全边界

Skill 不能绕过客服岗位权限、RAG owner/team/grant 授权或高风险审批。大模型只生成草稿和建议，不代表已经外部发送、退款或赔付。

外部执行与重试只传客户正文和必要路由字段，不传内部建议、转人工原因或原始模型输出。未通过结构校验的旧版混合草稿需重新生成并审核后使用。
