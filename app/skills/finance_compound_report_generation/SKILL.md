# 财务报表与工资表复合生成 Skill

## 适用场景

- 用户要求生成财务报表、财务月报、经营汇总表、经营分析表。
- 用户一句话里同时要求生成财务报表和工资表，例如“帮我生成这个月的财务报表和工资表”。
- 用户使用同义表达时也应识别，例如工资表、薪资表、薪水表、薪酬表、payroll、salary report。

## 业务规则

- 用户说了几个输出，就生成几个输出。
- 默认不合并文件；只有用户明确说“合并成一张表”“放到一个 Excel”“一个文件”等，才生成合并工作簿。
- “本月/这个月”按当月 1 号到当月最后一天处理。
- “从某天到现在”按起始日期到当天处理。
- 财务报表读取并归类汇总财务权限内的经营数据：GL Entry、Payment Entry、Sales Invoice、Purchase Invoice。
- 工资表只读取 Salary Slip。
- 没有要求发送邮箱或微信时，只在聊天里输出并生成可下载附件。

## 权限规则

- 仅财务岗位或管理员可执行。
- 非管理员必须启用 `automation-report_analysis`。
- 如果请求中包含工资表，非管理员还必须启用 `automation-salary_summary`。
- ERP 资源权限必须在 Skill Registry / Skill Executor 和后端 executor 前置校验，不能交给大模型决定。
- Skill 选择可以由 ReAct 或大模型辅助判断，Skill 执行必须由后端 executor 完成。
- 生成、保存、邮件发送和失败都必须进入运行记录或审计链路。

## 执行步骤

1. 识别用户是否要求财务报表、工资表或两者都要。
2. 解析期间，例如本月、上月、指定月份、从某天到现在。
3. 通过 Skill Registry / Skill Executor 校验岗位、AI 应用启用状态和 ERP 资源范围。
4. 财务报表并发查询 GL Entry、Payment Entry、Sales Invoice、Purchase Invoice。
5. 工资表查询 Salary Slip。
6. 使用 openpyxl 生成一个或多个 Excel。
7. 保存可下载附件，写入运行记录和审计日志。
8. 返回中文业务说明和附件列表。

## 输出格式

- 返回中文业务说明。
- 返回一个或多个 Excel 附件。
- 附件 metadata 需要包含期间、ERP 资源、生成文件名、下载路径和产物 ID。
- 如果关键数据缺失，回复“缺少【某某某】数据，是否继续生成？”。

## 安全边界

- 大模型只能参与 Skill 选择和用户意图理解，不能直接执行 ERP 查询、生成文件、发送文件。
- 后端 executor 必须重新校验权限，不能信任聊天里的自然语言判断。
- 不允许越过财务岗位读取客服、运营或其他非财务 ERP 资源。
- 不允许在用户没有明确要求时发送邮箱或微信。
- 微信发送属于高风险动作，需要单独联系人确认、审批和审计，本 Skill 默认只生成附件。
